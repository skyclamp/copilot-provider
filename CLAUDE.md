# copilot-provider — agent guide

A thin proxy that exposes GitHub Copilot's Responses API to Codex (gpt
models) and grok-build (grok models). **Node.js + TypeScript + Express**,
compiled with `tsc` to `dist/`.

## Runtime

- **Node.js >= 24** (see `engines` in [package.json](package.json)).
  Production runs the compiled `dist/index.js`; `npm run dev` runs the `.ts`
  sources directly via Node's type stripping, so only erasable TypeScript
  syntax is allowed (`erasableSyntaxOnly` — no enums, namespaces, or
  parameter properties).
- ES modules (`"type": "module"`, `module: NodeNext`). Keep `.ts` extensions
  in relative import specifiers — `tsc` rewrites them to `.js`
  (`rewriteRelativeImportExtensions`). Use `import type` for type-only
  imports (`verbatimModuleSyntax`).
- `.env` is loaded by `node --env-file-if-exists=.env` in the npm scripts; do
  not add `dotenv`.
- Dependencies are intentionally minimal: `express` is the only runtime
  dependency. Prefer `node:` built-ins and the global `fetch` / Web Streams
  over adding packages.

## Common commands

```sh
npm run build                    # tsc → dist/ (required before start / scripts)
npm start                        # node dist/index.js on $PORT (default 4141)
npm run dev                      # watch mode on the .ts sources
npm run auth                     # GitHub device-flow login → prints CAPI_TOKEN for .env
npm run setup-device             # generates VSCODE_*/EDITOR_DEVICE_ID for .env
npm run gen-keys                 # mints client API keys into keys.json
npm run fetch-models -- --token <gh-token>   # prints the upstream Copilot /models payload (debug only)
npm run typecheck                # tsc --noEmit
npm test                         # node --test on tests/**/*.test.ts
```

No linter is configured.

## Architecture

Entry point [index.ts](index.ts) parses CLI arguments (`--capi-token`,
`--capi-ghe-host`, `--port`, `--disable-client-auth`; they override `CAPI_TOKEN`,
`CAPI_GHE_HOST`, `PORT`, `DISABLE_CLIENT_AUTH`) and
starts the Express app exported by [src/server.ts](src/server.ts). The server
only exposes:

- `GET /`, `HEAD /` — health check (grok-build prewarms its connection with `GET /`)
- `POST /responses` → upstream `{api}/responses` ([src/responses.ts](src/responses.ts))

Anything else returns `404 null`. See [docs/design.md](docs/design.md) for
the upstream-path contract — `/responses` has no `/v1` prefix locally or
upstream.

### Module layout (`src/`)

| File | Role |
|------|------|
| `server.ts` | Express app, auth, routing, Express ⇄ Web `Request`/`Response` adapter |
| `proxy.ts` | `getProxyContext()`, `buildResponseHeaders()`, header builder |
| `copilot-token.ts` | GitHub token → Copilot token exchange + caching |
| `constants.ts` | URLs and API versions |
| `responses.ts` | `/responses` proxy |
| `responses-stream.ts` | Responses SSE output item ID normalization |
| `session.ts` | Client identification (`cx` Codex / `gb` grok-build), upstream session-id mapping |
| `grok.ts` | grok-build request kind (main / subagent / compaction / background) → VS Code Chat headers |
| `keys.ts` | Client API-key resolution |
| `types.ts` | Shared types (`RequestContext`, `ProxyContext`, …) |

`proxyResponses` takes a `RequestContext` and returns a Web `Promise<Response>`.
`server.ts` converts the Express request into a Web `Request` (body streamed,
not parsed), performs auth, and pipes the returned `Response` back. A client
disconnect aborts `req.signal`, which cancels the upstream `fetch`.

### Proxy contract (do not break)

- **Request pass-through.** Do not validate request bodies. The only body
  reads/edits are `X-Initiator` detection from `input` and the
  `gpt-5.6-sol` fast-tier model rewrite in `responses.ts`. CAPI returns usage
  by default, so do not inject a usage request field.
- **Errors are pass-through too.** Forward upstream status + body verbatim;
  only synthesise a `502` when the proxy itself fails.
- **Streaming is direct.** Return the upstream `ReadableStream` without teeing
  or buffering it; SSE only passes through the output item ID normalization
  in `responses-stream.ts`.
- Never synthesise `output_config` if absent.

### Auth

Two-sided:

1. **Outgoing** — `getCopilotToken()` exchanges `CAPI_TOKEN` for a
   short-lived Copilot token via the device endpoint; cached in memory.
2. **Incoming** — clients must present an API key from `keys.json` in the
   working directory (override with `KEYS_FILE`; gitignored, generated by
   `npm run gen-keys`):
   - `/responses`: `Authorization: Bearer <key>`
   - Set `DISABLE_CLIENT_AUTH=true` (or pass `--disable-client-auth`) to bypass (`apiKeyId` becomes
     `'noauth'`).
   Invalid keys get `404 null` (intentional — same shape as unknown route).

## Environment variables

See [.env.example](.env.example). Required for normal operation:

- `CAPI_TOKEN` (or `--capi-token`), `VSCODE_MACHINE_ID`,
  `EDITOR_DEVICE_ID` — populated by `npm run auth` + `npm run setup-device`.
- `COPILOT_CHAT_VERSION`, `VSCODE_VERSION`, `GITHUB_API_VERSION` — sent in
  upstream headers; bump these to track real Copilot Chat releases.
- `PORT` (default `4141`, or `--port`).

Optional settings: `DISABLE_CLIENT_AUTH`, `KEYS_FILE`, `CAPI_GHE_HOST` (GitHub
Enterprise host, or `--capi-ghe-host`). `MODELS_API_VERSION` is only read by
the `npm run fetch-models` debug script.

Read env vars via `process.env.X`.

The CAPI credentials are deliberately named `CAPI_TOKEN` / `CAPI_GHE_HOST`, not
`GITHUB_TOKEN` / `GH_TOKEN` / `GHE_HOST`: those are read by other tools as a
general-purpose GitHub PAT, while this token is only for CAPI. Do not add
fallbacks to the generic names.

## Conventions

- Keep modules small and direction-of-flow obvious: server → proxy helper
  → endpoint module → upstream `fetch`.
- Don't add docstrings, comments, or refactors to code you didn't change.
- Don't introduce new dependencies without a clear reason — this proxy is
  meant to stay tiny.
- Logging: one-line `[proxy]` / `[server]` prefixed lines via
  `console.log` / `console.error`. No logger library.
- File I/O: `node:fs/promises` (or `node:fs` sync reads at startup).
- Types: handlers return a Web `Promise<Response>` and take a
  `RequestContext` (`{ req, apiKeyId }`) defined in `src/types.ts`.
